# 저장 데이터와 백업

게임 기록은 같은 출처의 IndexedDB에 저장한다. 다른 기기나 브라우저로 옮길 때는 **설정 → 백업 및 데이터 이동 → 저장 데이터 내보내기**로 `.bpz` 파일을 받은 뒤, 대상 브라우저의 **저장 데이터 가져오기**에서 연다. 파일을 선택하면 먼저 **백업 확인** 창이 열린다.

## 브라우저에 저장되는 값

IndexedDB 이름은 `bus-puzzle`, 데이터베이스 버전은 `1`이다. `state` 객체 저장소의 `save` 키 한 곳에 `{ revision, data, writer }`를 기록한다. `revision`은 이 레코드를 쓸 때마다 증가하는 정수이고 `writer`는 저장소 인스턴스마다 발급한 식별자다. 백업으로 내보내는 게임 기록은 안쪽의 `data`다. [저장소 구현](../src/storage/save-repository.ts)

| `data` 필드                | 내용                                                                                                                                                            |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `saveSchemaVersion`        | 게임 기록의 형식 버전. 현재 값은 `5`다.                                                                                                                         |
| `settings`                 | 효과음, 진동, 프레임 레이트와 모션 줄이기 값. 새 기록은 효과음 켜짐, 진동 꺼짐, 60FPS로 시작하며 최초 모션 설정은 브라우저의 `prefers-reduced-motion`을 읽는다. |
| `roundProgressById`        | 라운드·정류장 ID별 클리어 여부, 최초·최근 클리어 시각, 횟수, 클리어한 콘텐츠 리비전.                                                                            |
| `depotRun`, `promenadeRun` | 기본 정류장과 이전 산책로 배치의 진행 기록. 이전 파일에서는 필드가 없을 수 있다.                                                                                |
| `activeRun`                | 클래식 모드의 라운드 ID, 콘텐츠 리비전과 게임 상태. 진행 중인 클래식 라운드가 없으면 `null`이다.                                                                |
| `backupReminderDismissed`  | 백업 안내를 닫았는지 기록한다.                                                                                                                                  |

### 저장 도중 새로고침하거나 다른 탭이 저장한 경우

1. `useSave.mutate`가 화면과 메모리의 현재 값을 갱신하고, 탭의 `sessionStorage`에 `bus-puzzle:pending`을 쓴다. 여기에는 작성자, 기준 리비전과 최신 게임 데이터가 들어간다. 이 임시 저장소가 차 있거나 사용이 제한되어도 IndexedDB 쓰기는 시도한다.
2. 같은 탭의 쓰기 요청은 순서대로 실행한다. 각 요청은 데이터를 현재 형식으로 검증한 다음, 읽기·쓰기 트랜잭션 안에서 디스크의 리비전을 다시 확인한다. 일치하면 다음 리비전과 게임 데이터를 함께 커밋한다. 커밋한 값이 가장 최근의 임시 저장일 때만 해당 임시 항목을 지운다.
3. 새로고침하면 유효한 임시 저장이 있는지 확인한다. 기준 리비전이 현재 디스크 값과 같거나 디스크에 마지막으로 쓴 작성자가 임시 저장의 작성자와 같으면 최신 값을 복구할 수 있다. 다른 탭이 새 리비전을 커밋했다면 디스크의 기록을 사용한다.
4. 성공한 쓰기는 `bus-puzzle-updates` 채널로 다른 탭에 알린다. 알림을 받은 탭이나 리비전 불일치를 발견한 탭은 쓰기를 중단한다. 이때 해당 탭에서 진행한 내용은 먼저 내보낸 뒤 새로고침하면 된다. 내보내기는 메모리에 있는 최신 값을 읽는다.

정류장 화면은 출차·되돌리기, 탑승 인원과 차량 상태 등 화면에 표시할 값의 변경, 진행 중인 판의 메뉴 열기에서 체크포인트를 남긴다. 클리어할 때는 마지막 체크포인트와 클리어 횟수를 한 데이터에 담아 기록한다. [저장 훅](../src/storage/use-save.ts) · [정류장 화면](../src/game/depot/DepotGame.tsx) · [다중 탭·새로고침 테스트](../tests/storage.test.ts)

## 이전 버전 이어하기

저장 형식은 읽을 때 메모리에서 현재 버전으로 변환한다. 복구할 임시 저장이 없으면 이때 IndexedDB의 리비전은 그대로다. 화면에서 기록이나 설정이 바뀌면 다음 저장에 현재 형식을 쓴다. [스키마와 변환 함수](../src/storage/save-schema.ts)

| `saveSchemaVersion` | 현재 앱의 읽기 동작                                                                                                                                        |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1                   | `backupReminderDismissed`를 `false`로 채운다. 과거 절전 설정이 있으면 60FPS로 변환한다.                                                                    |
| 2                   | 저장된 백업 안내 여부를 유지한다. `powerSavingMode`가 `auto`, `on`, `off` 중 어느 값이든 60FPS로 옮긴다. v1·v2 모두 이미 `frameRate`가 있는 설정도 읽는다. |
| 3                   | 프레임 레이트와 진행 기록을 검증한다. 순환 속도 전환 시점이 없는 기록도 마지막 저장 시각까지 당시의 속도로 재생한 뒤 이어갈 수 있다.                       |
| 4                   | 정속 순환 전환점이 담긴 기록을 읽을 수 있다. 차량 구성과 출차 시각을 보존하고 형식 번호를 5로 올린다.                                                      |
| 5                   | 현재 스키마로 검증한다. 정류장 기록은 차량 구성 버전 1~4를 허용한다.                                                                                       |

더 큰 형식 번호를 가진 파일은 가져오기를 중단하고 앱 업데이트를 안내한다. 기기에 이미 저장된 데이터가 더 새 버전이면 새 기록으로 복구하는 동작도 차단한다.

### 정류장 체크포인트와 되돌리기

`DepotRun.version`은 현재 `1`이다. 체크포인트에는 배치 종류(`layout`), 차량 구성 버전(`fleetVersion`), `stageId`, 마지막 논리 시각 `elapsed`와 성공한 출차 목록 `moves`가 들어간다. 각 출차는 차량 ID `id`와 출차한 논리 시각 `at`을 기록한다. 최대 64개이며 시각은 앞에서부터 같거나 커야 하고 모두 `elapsed` 이하여야 한다. 복원할 때 같은 판을 생성해 출차 사이의 시간을 진행시키고 마지막 시각까지 재생해 승객과 차량의 위치, 탑승 인원, 좌석 예약을 다시 계산한다. [세션 코드](../src/game/depot/session.ts) · [정류장 엔진](depot-engine.md)

기본 정류장(`compact`)에서 차량 구성 1은 16·20·24인승을 쓴다. 구성 2는 16·24·32·48인승을 쓰고, 구성 3은 5·8·10색과 직각 배치, 구성 4는 같은 색 구성에 대각선 주차를 적용한다. 이미 출차한 판은 기록에 담긴 구성으로 재생한다. 출차가 없는 구형 판이나 구형 판의 마지막 출차를 되돌린 경우에는 같은 단계의 최신 배치로 시작한다. `layout`이 없는 기록은 이전 산책로 배치로 해석하며, 새 기본판의 진행 상황을 쓸 때 해당 산책로 기록을 별도로 보관한다.

시간 관련 필드는 규칙을 바꾸기 전 출차까지 재현하는 데 사용한다.

| 필드                  | 이 시점에 달라지는 동작                                                                                    |
| --------------------- | ---------------------------------------------------------------------------------------------------------- |
| `fasterPaceFrom`      | 초기 버전의 차량 주행·승차 규칙을 쓰던 구간이 끝난다.                                                      |
| `orderedBoardingFrom` | 기본 정류장은 왼쪽 줄부터 비우는 규칙으로 전환하고, 이후 새로 탑승하는 승객은 좌석별 도착 간격을 적용한다. |
| `steadyBeltFrom`      | 이때의 승객 위치를 기준으로 순환로가 일정한 속도로 움직인다.                                               |

세 값은 위 표의 순서를 지키며 마지막 값은 `elapsed` 이하다. 이전 파일에서 `steadyBeltFrom`이 없으면 마지막 저장 시각을 전환점으로 쓰고, `orderedBoardingFrom`과 `fasterPaceFrom`도 빠졌으면 각각 다음 전환점의 값을 사용한다. 재생 과정에서 출차 직전 상태도 다시 만들어 두므로, 이어하기 직후에도 한 수 되돌릴 수 있다. 기록된 출차를 재현할 수 없으면 해당 단계에서 새로 시작한다. 클래식 모드는 별도로 콘텐츠 리비전과 출차 기록을 검사하고 재생 결과를 저장된 상태와 비교한다. [세션 호환성 테스트](../tests/depot-session.test.ts) · [클래식 이어하기 검사](../src/storage/save-schema.ts)

## BPZ 파일 형식

일반 백업 파일 이름은 `bus-puzzle-save-YYYY-MM-DD.bpz`다. 날짜는 내보낸 시각의 UTC 날짜다. 파일은 UTF-8 JSON 하나를 레벨 3의 Zstandard 프레임으로 압축한 데이터이며, 프레임의 첫 네 바이트는 `28 B5 2F FD`다. 압축·해제 모듈은 처음 사용할 때 로드하고 프로덕션 서비스 워커는 WASM을 미리 캐시한다. [파일 읽기·쓰기](../src/storage/import-export.ts) · [오프라인 빌드 설정](../vite.config.ts)

빈 게임 기록을 내보냈을 때의 JSON 예시다. 바깥의 형식 번호와 `data.saveSchemaVersion`이 같아야 하며 `exportedAt`은 UTC 시각 문자열이다.

```json
{
  "format": "bus-puzzle-save",
  "saveSchemaVersion": 5,
  "exportedAt": "2026-11-21T08:00:00.000Z",
  "data": {
    "saveSchemaVersion": 5,
    "settings": {
      "soundEnabled": true,
      "hapticsEnabled": false,
      "frameRate": 60,
      "reducedMotion": false
    },
    "roundProgressById": {},
    "activeRun": null,
    "backupReminderDismissed": false
  }
}
```

Zstandard CLI가 있으면 빈 디렉터리에 앱에서 내보낸 파일을 `game.bpz`라는 이름으로 복사한 뒤 다음 명령으로 확인할 수 있다. 마지막 명령이 만든 `repacked.bpz`도 앱에서 가져올 수 있다.

```sh
zstd -t game.bpz
zstd -d game.bpz -o game.json
zstd -3 game.json -o repacked.bpz
```

### 입력 검증

- 일반 백업 내보내기와 가져오기는 압축 파일과 복원된 JSON을 각각 **2 MiB(2,097,152바이트)**까지 허용한다. Zstandard 프레임에 원문 크기가 있으면 WASM 버퍼를 할당하기 전에 검사한다. 크기를 생략한 프레임은 최대 2 MiB의 출력 버퍼로 해제한다.
- 가져오기는 확장자를 대소문자 구분 없이 확인한다. `.bpz`는 Zstandard 및 예전 gzip 백업을 읽고, `.json`은 예전 평문 백업을 읽는다. gzip은 헤더와 끝에 기록된 크기를 확인하고 해제 과정에서 실제 출력 크기도 센다.
- UTF-8 디코딩, JSON 파싱, 바깥 형식·버전 검사, 안쪽 데이터 검증을 모두 마친 뒤에만 미리보기를 연다. 크기 초과, 파일 잘림, 형식 번호 불일치로 거절된 파일은 현재 게임 기록에 적용되지 않는다. [검증 및 파일 호환성 테스트](../tests/storage.test.ts)

## 병합, 교체, 복구

**기록 병합**은 라운드 ID별로 처리한다. 새 ID는 추가하고 같은 ID는 최초 클리어 시각의 최솟값, 최근 클리어 시각의 최댓값을 택한다. 클리어 여부는 둘 중 하나라도 클리어했으면 참이고, 횟수와 콘텐츠 리비전은 각각 큰 값을 쓴다. 따라서 횟수 3과 2인 같은 기록을 병합하면 3회다. 현재 앱의 목록에 없는 라운드 ID도 보관한다. [병합 함수](../src/storage/import-export.ts)

| 백업 확인 화면의 선택   | 저장되는 내용                                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 기록 병합               | 클리어 기록을 합치고 현재 설정과 진행 중인 판을 유지한다.                                                                      |
| 설정 가져오기           | 병합 시 백업의 설정 전체를 적용한다.                                                                                           |
| 진행 중 라운드 가져오기 | 병합 시 `activeRun`, `depotRun`, `promenadeRun` 세 값을 백업 값으로 함께 교체한다. 백업에서 빈 항목은 대상에서도 비게 된다.    |
| 백업으로 완전히 교체    | 교체 확인란을 선택하면 백업의 설정과 기록 전체를 적용한다. 교체 전의 상태는 같은 창에서 **현재 기록 백업**으로 내보낼 수 있다. |

**저장 데이터 복구**는 기기 기록 자체를 읽지 못했을 때 표시된다. **원본 데이터 내보내기**로 받는 `bus-puzzle-recovery-YYYY-MM-DD.bpz`에는 IndexedDB의 원래 `data`를 JSON으로 직렬화한 값이 들어간다. 이 파일의 용도는 원본 확인과 수동 복구다. 위 CLI로 해제할 수 있으며, 일반 가져오기 화면은 위 예시에 있는 `format`, `exportedAt`, `data`를 갖춘 일반 백업을 요구한다. 원본 보관이 끝나고 **새 기록으로 복구**를 확인하면, 지원하는 버전의 기존 레코드를 `state`의 `recovery-<밀리초 시각>` 키로 옮겨 보관하고 빈 기록을 같은 트랜잭션에서 쓴다. 이후 보관해 둔 일반 백업을 가져올 수 있다.
