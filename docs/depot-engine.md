# 정류장 엔진

기본 화면에서 여는 정류장은 `layout: 'compact'`를 사용한다. `createDepot`가 한 판의 차량과 승객을 만들고, `dispatchBus`가 플레이어의 출차 입력을 처리한다. 이후 차량 이동, 승객 합류, 탑승, 승패는 `tickDepot`이 계산한다. 화면 없이 이 세 함수만 호출해도 한 단계를 끝까지 진행할 수 있다. [엔진](../src/game/depot/logic.ts) · [게임 화면](../src/game/depot/DepotGame.tsx)

## 단계와 초기 배치

현재 새 판의 `fleetVersion`은 4다. 세 단계 모두 차량 57대, 승강장 7칸이다. 정원별 차체 길이와 폭은 SVG 좌표 기준으로 16인승이 36×27, 24인승이 39×28, 32인승이 43×29, 48인승이 47×30이다. 바깥쪽 두 대는 각각 −55°, +55°로 주차하고, 안쪽 두 줄에는 각각 −45°, +45° 차량이 다섯 대씩 놓인다.

| 단계             | 새로 등장하는 색               | 전체 색 수 | 전체 승객 | 시작 시 대기 줄 |
| ---------------- | ------------------------------ | ---------: | --------: | --------------: |
| 1. 등대 선착장   | 파랑, 노랑, 빨강, 하늘색, 회색 |          5 |     1,784 |           1,616 |
| 2. 파도길 정류장 | 초록, 주황, 보라               |          8 |     1,720 |           1,552 |
| 3. 노을 부두     | 남색, 흰색                     |         10 |     1,752 |           1,584 |

각 단계에서 처음부터 모든 색의 승객이 순환한다. 3단계의 `isBlindBus`는 주차 중인 차의 진행 경로가 막혀 있을 때 검정과 물음표를 표시한다. 차에는 처음부터 실제 색이 있고 경로가 열리는 순간 그 색이 보인다. 회색(`gray`)에는 별도의 승객과 좌석이 있다. [단계 이름과 색상](../src/game/depot/stages.ts) · [차량 표시](../src/game/depot/DepotBoard.tsx)

`makeCompactFleet`는 단계와 버전으로 좌표, 방향, 정원, 색, 차량 ID를 결정한다. 배치를 만든 뒤 각 차량의 출구까지 가로막는 차량 목록을 계산한다. 목록의 선행 차량이 모두 빠진 후보를 정해 둔 우선순위로 하나씩 골라 `order`에 넣는다. 아직 차가 남았는데 후보가 없으면 서로 막는 배치이므로 초기화가 실패한다. 이 순서는 차량의 출차 가능성을 확인하고 승객을 배분하는 데 쓰인다. 일곱 승강장의 수용 여부까지 포함한 풀이는 별도의 게임 테스트가 확인한다. [배치 생성](../src/game/depot/logic.ts) · [단계별 풀이 테스트](../tests/depot-logic.test.ts)

## 출차 방향과 충돌 판정

게임판은 `400 × 760` 좌표계를 쓴다. 각도 0°는 위쪽, +90°는 오른쪽이다. 각도를 라디안 `θ`로 바꾸면 전진 벡터는 `(sin θ, -cos θ)`다. `laneExit`는 차량 중심에서 이 방향으로 나아가 주차장 도로 경계에 처음 닿는 지점과 거리를 구한다. 도로 경계는 가로 13~387, 세로 350~663이다.

`hitsOnExit`는 두 차체를 회전된 직사각형(OBB)으로 취급한다. 두 차량 각각의 앞 방향과 옆 방향, 총 네 방향에 차체를 투영한다. 선택한 차량이 출구까지 직진할 때 각 방향에서 두 투영 구간이 겹치는 이동 거리 범위를 구하고, 네 범위가 공통으로 겹치면 막힌 것으로 판정한다. `getBlockers`는 주차 중인 차와 아직 주차장 출구에 도달하지 않은 주행 차량을 검사한다. 주행 차량에는 `busPose`로 계산한 현재 좌표와 방향을 쓴다. 예를 들어 1단계 `bus-34`는 −45°를 향하고, `bus-2`, `bus-3`, `bus-4`, `bus-28`이 경로에서 모두 빠져야 출차할 수 있다. [충돌 판정](../src/game/depot/logic.ts) · [대각선 주행 테스트](../tests/depot-logic.test.ts)

| 차량 상태  | 다음 상태로 넘어가는 조건                      | 승강장 처리            |
| ---------- | ---------------------------------------------- | ---------------------- |
| `parked`   | 출차 요청이 들어오고 경로와 승강장이 비어 있다 | 왼쪽부터 첫 빈 칸 예약 |
| `driving`  | 예약한 승강장까지 경로를 모두 주행했다         | 예약 유지              |
| `boarding` | 마지막 승객이 실제로 착석했다                  | 만석이 되면 출발       |
| `leaving`  | 출발 경로를 끝까지 주행했다                    | 이때 칸 해제           |
| `gone`     | 차량 운행 완료                                 | 빈 칸                  |

경로가 막히면 `dispatchBus`는 `blocked`와 첫 방해 차량의 ID를 돌려준다. 경로가 열려도 승강장이 모두 사용 중이면 `full`을 돌려준다. 출차가 성공하면 `routeToBay`가 주차장 출구, 외곽 도로, 승강장 진입점을 연결한다. `roundedRoute`가 모서리를 2차 베지어 곡선으로 다듬고, `busPose`는 경로에 쌓인 주행 거리로 화면 좌표와 방향을 계산한다. [경로와 차량 상태](../src/game/depot/logic.ts)

## 대기 줄에서 좌석까지

1. **승객 배분.** `passengerSequence`는 각 색의 승객 수를 같은 색 차량의 총정원에 맞춘다. `openingGroups`가 첫 무리의 색 순서를 정하고, 이미 배정한 승객을 차량별 정원에서 뺀 뒤 남은 인원을 출차 순서에 맞춰 붙인다. 첫 168명은 순환로에, 나머지는 `queue`에 들어간다.
2. **대기 줄.** `queue`는 하나의 FIFO 배열이다. `rightFrontId`는 대기 인원을 4명씩 한 행으로 세어 좌우 두 통로에 나누는 ID 경계를 구한다. `activeQueueSide`는 맨 앞 승객의 ID로 어느 쪽 차례인지 결정한다. 왼쪽의 마지막 승객이 실제로 합류한 뒤에야 오른쪽에서 예약을 시작한다.
3. **순환로 합류.** 순환로에는 42행 × 4명분의 자리(`carrier`)가 있다. `advanceQueue`는 현재 비어 있고 0.62초 이내에 해당 통로 입구를 지날 자리를 찾는다. 도착 시각, 자리 번호 순으로 후보를 살펴보고 앞사람이 걸어서 제때 닿을 수 있는 자리를 `entering`에 예약한다. 합류 시각이 된 승객만 줄 앞에서 차례로 빼서, 같은 ID와 색으로 예약한 자리에 옮긴다.
4. **좌석 예약.** 순환 중인 승객이 탑승 지점을 지날 때 같은 색의 `boarding` 차량을 찾는다. 후보의 빈 좌석은 `정원 − 착석 인원 − 이미 그 차로 걷고 있는 인원`이다. 빈 좌석이 있으면 승객에 `busId`와 `boardingTrip`을 기록한다. 조건에 맞는 차량이 여러 대이면 차량 배열에서 먼저 만나는 쪽을 선택한다. 버스로 걷기 시작하면 순환로의 자리는 다음 대기 승객에게 열리지만, 착석 인원은 문에 도착할 때 증가한다.

1단계 시작 시 순환로에는 파랑 32명, 노랑 48명, 빨강 32명, 하늘색 28명, 회색 28명이 있다. 파란 48인승 한 대만 보내면 32명이 타고, 그만큼 열린 자리에 대기 줄 맨 앞의 노란 승객 32명이 들어온다. 남은 파란 승객 16명은 그 뒤에 있다. 이때 노란 차량을 보내면 순환로에 자리가 생겨 파란 차도 만석이 될 수 있다. [승객 배분과 탑승](../src/game/depot/logic.ts) · [대기 순서와 부분 탑승 테스트](../tests/depot-logic.test.ts)

승객 수를 점검할 때는 `queue.length + passengers.length + boardedCount === totalPassengers`를 사용한다. 합류 중인 승객은 아직 `queue`에, 착석하러 걷는 승객은 아직 `passengers`에 포함된다. 따라서 `entering.length`나 보행 인원을 별도로 더하면 중복 집계된다.

## 시간과 렌더링

| 값                                  | 단위 및 역할                                                                                                      |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `tickLiveDepot(state, realSeconds)` | 실제로 진행할 초를 받고 2.5를 곱해 `tickDepot`에 전달한다.                                                        |
| `elapsed`                           | 차량 주행과 좌석 도착 예약에 쓰는 논리 시간. 새 판의 주행 속도는 논리 초당 488좌표 단위다.                        |
| `beltTime`                          | 승객 순환과 통로 합류에 쓰는 시간. 정속 구간에서는 논리 시간 증가분을 2.5로 나눠 기준 시점에 더한다.              |
| `FRAME_RATE`                        | 엔진이 차량·승객 상태를 갱신하는 간격은 논리 시간 1/60초다.                                                       |
| `settings.frameRate`                | 화면을 그리는 목표 빈도다. 60·90·120FPS를 선택할 수 있고 실제 갱신은 브라우저의 `requestAnimationFrame`을 따른다. |

차량이 정차해 탑승을 시작해도 순환로 중심선을 따라 진행하는 속도는 실제 초당 86좌표 단위다. 같은 차량에 예약된 다음 승객의 도착 시각은 `max(지금 + 0.7, 이전 예약 도착 + 0.125)` 논리 초 기준으로 잡는다. 실시간으로 환산하면 탑승 지점에서 문까지 최소 280ms, 같은 차량의 연속 착석 간격은 최소 50ms다. 좌석이 비어 있어도 해당 색 승객이 탑승 지점에 오기까지 걸리는 시간은 별도다.

`tickDepot`는 누적 `elapsed`에서 이전·다음 물리 프레임의 번호를 계산한다. 호출이 프레임 중간에 끝나면 순환로 표시 시간은 그 나머지 구간까지 반영한다. 같은 출차 입력과 논리 시각으로 재생하면 렌더 호출을 다르게 나눠도 차량 상태, 승객과 큐 순서가 재현된다. UI는 탭이 숨겨지거나 패널이 열리면 틱을 멈추고, 다시 그릴 때 한 번에 넘기는 실제 경과 시간은 0.2초로 제한한다. `DepotBoard.paint`는 최신 좌표를 SVG에 적용하고, `DepotGame`은 좌석 수·차량 상태·표시 승객처럼 화면 구성이 바뀌면 React 상태를 갱신한다. ## 승패와 힌트

모든 차량이 `gone`이 되면 승리한다. `canAdvance`는 주행·퇴장 중인 차량, 진행 중인 탑승이나 합류, 움직일 수 있는 대기 줄, 정차 차량과 같은 색의 순환 승객을 확인한다. 자동으로 더 진행할 수 없을 때, 빈 승강장이 없거나 출차 가능한 주차 차량이 없으면 패배한다. 따라서 일곱 칸을 모두 사용해도 착석이나 퇴장이 진행 중이면 그 결과를 기다린다.

`recommendBus`는 빈 승강장이 있을 때 출차 가능한 차량을 `serviceOrder` 순서로 살핀다. 현재 버전의 첫 수는 그중 첫 차량이다. 이후에는 순환 승객과 곧 빈자리를 채울 대기 승객, 이미 같은 색 버스로 걷는 인원을 세고, 승강장에 예약된 같은 색 좌석 수까지 고려해 만석을 만들 수 있는 차를 먼저 권한다. 적합한 차가 없고 자동 진행이 가능하면 기다린다. 자동 진행도 멈추면 출차 가능한 첫 차량을 권한다. [힌트와 종료 조건](../src/game/depot/logic.ts)

## 배치 변경과 회귀 검사

`compact` 배치 v1은 16·20·24인승, v2부터는 현재의 네 정원을 사용한다. v1·v2의 단계별 색 수는 3·5·8이며, v3에서 5·8·10색으로 늘었다. 대각선 배치는 v4에서 도입됐다. 저장된 출차 기록은 당시의 차량 ID, 색 순서, 차체 크기와 출구 위치에 의존하므로 이 값을 변경할 때는 기존 배치를 재생할 수 있게 버전을 구분한다. 구형 `promenade`는 별도 배치로 유지되며 승강장 세 칸과 72행의 순환로를 사용한다.
